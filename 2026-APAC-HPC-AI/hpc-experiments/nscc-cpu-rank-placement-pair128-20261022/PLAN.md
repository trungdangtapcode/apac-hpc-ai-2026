# Default-Scotch runtime rank-placement pair

## Question and prior evidence

Does binding the existing default-Scotch N128 ranks to CPU cores selected by a graph-aware, balanced eight-group mapping improve the 40-step native solve time on one exclusive ASPIRE-2A node? The mapping leaves rank IDs, processor directories, partition cells, mesh, source code, physics, solver controls, and decomposition unchanged. The offline graph screen reduced logical cross-group face weight from 371,658 to 354,658 (17,000 faces, 4.5741%); this graph metric is only a candidate-selection heuristic, not measured traffic or speedup. The frozen screen and renderer are copied into the payload and pinned by hashes.

Both arms use the same accepted default-Scotch N128 artifact and manifest. Each gets an isolated per-job working copy so the accepted source remains unchanged. Before either arm initializes, both copies explicitly restore original zero-time fields and their field seals must match. Each arm then runs the complete `renumberMesh -constant -overwrite -parallel`, `potentialFoam -initialiseUBCs -parallel`, `applyBoundaryLayer -ybl 0.0450244 -parallel`, and 40-step `simpleFoam -parallel` chain. The control uses site-default rank placement; the candidate uses the frozen group mapping rendered into a PALS CPU list from the same allocation's fresh topology probe. Copy time and scratch-space overhead are unmeasured; if staging and checks do not finish within the wrapper deadline, the pair aborts without a timing result.

## Placement gates

Before initialization, an unbound 128-rank probe must establish one host, 128 unique physical cores, single-CPU rank affinity, and eight distinct NUMA nodes each holding one contiguous 16-rank default block. The renderer derives the candidate CPU list from those probed CPU sets and the frozen mapping. A second MPI probe applies that exact list; every candidate rank must match its expected CPU, physical core, and NUMA node before expensive initialization starts. Any mismatch or topology change aborts the job. CPU IDs from historical nodes are never reused.

The candidate binding applies to all its MPI initialization and solver stages. Both arms set `OMP_NUM_THREADS=1` and identical explicit transport values `FI_VERBS_PREFER_XRC=0` and `FI_OFI_RXM_USE_SRX=1`; transport is held constant. SRX-off is already used in shared jobs, so this is a same-allocation causal rank-placement comparison, not a newly discovered SRX-off tactic. Startup probes establish launch affinity only; they do not measure solver-time migration, memory-page placement, traffic, or MPI waits.

## Allocation and acceptance

The unsubmitted request is one exclusive node, 128 MPI ranks/CPUs, 440 GB, zero GPUs, normal routing, and 29 minutes. The maximum reservation is **61.866667 SU** at one SU per core-hour. A wrapper deadline at 28:30 bounds expensive commands and retains 30 seconds for cleanup; PBS walltime remains the hard limit, and an EXIT trap cannot be relied on after SIGKILL or node failure. Wrapper timing is only diagnostic; terminal PBS state and billed cost require scheduler accounting. Submission is gated by resolution of the existing shared CPU controller/ownership, combined active-job caps, budget and queue capacity.

Input gates pin accepted default-Scotch source-file hashes, require `CUT_READY` for 128 ranks, Scotch, and 65,334,765 cells, and require exactly `processor0` through `processor127`. Every mandatory stage must exit successfully and pass native log checks for OpenFOAM 2512 double precision, 128 processes, clean completion, 40 ordered time steps, fixed solver iteration counts, finite force-coefficient rows and a finite native average step timer. The validator cross-checks all 39 native WCT samples against the wall-clock time-function samples, verifies accumulated time and the reported mean, and records median, p95, p99, maximum and slowest steps. A broad final drag-coefficient interval is a diagnostic sanity check only; it is not an official Basic-tier accuracy tolerance. The restored zero-time fields must match between arms, and each arm's post-initialization zero-time seal must still match after its solve.

An apparent candidate timing reduction is a one-pair observation only. Close this mapping branch if it improves native average step time by less than the preregistered **3% practical threshold**. A gain of at least 3% may justify considering a reverse-order confirmation only if the existing controller, budget and caps allow it; the single pair is not a stable-benefit claim. No result is available until the unsubmitted job is run; no four-node score is implied.
