# Iris full 150-step hierarchy-order pair

This bundle is a fresh matched full-work measurement, ordered **zyx first, then xyz**, using the already initialized per-order source trees at `/global/exafs/users/rdmaworkshop30/apac2026/tripleu-iris-order-init-20261026T133526Z/initialized/order-{zyx,xyz}`. Each candidate is copied independently into `WORK/cases/{zyx,xyz}`. Results and per-job status live under `WORK/runs/<SLURM_JOB_ID>/`; Slurm stdout, stderr, hardware inventory, and the module/runtime environment use the kit's `runs/` directory.

Each arm retains 56 ranks, hierarchical factors `(7 4 2)`, the original physics and function objects, and the fixed iteration solution. The copied run case changes only `system/controlDict:endTime` to `150`; its source `startFrom` value is retained and checked. The runner requires `fvSolution` to already match `fvSolution.fixedIter`. It does not modify the initialized source, patch solver code, use `LD_PRELOAD`/`LD_AUDIT`, rerun short exploratory work, or reuse the other arm's case tree.

The single exclusive-node Slurm request is three hours (168 allocated CPU-hours), with a 10,500-second internal deadline and 10,770-second outer timeout to leave scheduler cleanup margin. The zyx solver ceiling is 4,300 seconds and xyz ceiling is 5,400 seconds. Deadline guards reserve time for the second case copy and review. The effective solver cap may be reduced by the shared-deadline guard; it is recorded for each arm, and a solver that cannot finish all 150 steps is retained as incomplete rather than reported as a full result. Historical context for the guard is zyx's 50-step mean of 21.112004724 seconds per step, which suggests about 3,145 seconds for 149 timed intervals; this is a planning estimate, not a promise. The pair's full work is expected to fit the allocation, but actual runtime and copy costs remain to be established.

Before copying, `case_checks.py` validates the source against the 41 pinned case files and `READY` marker. `tree-manifest.py` records source and copy hashes, verifies all 56 processor trees and input symlinks, and rejects shared inodes. The runner byte-seals all 336 initialized time-zero fields in the source and clone, confirms the source remains unchanged afterward, and records runtime executable and linked-library identities before and after both arms. Whole-node `/proc` snapshots are collected before and after each solver; they are not per-process attribution or memory-bandwidth measurements.

The retained native parser requires exactly steps 1–150, 149 positive timings for steps 2–150, matching native and function-object timing data, all 150 force coefficient rows, finite values, fixed per-field iteration counts, one-node/56-rank log metadata, a native `End` marker, and zero GNU time exit status. Every preparation-stage and solver return code, timeout cap, elapsed time, source/copy checks, solver logs, stderr, resource record and procfs snapshot are preserved. Inspect the complete timing distribution, tail times, Cd trajectory, confidence warning, allocation diagnostics and runtime before interpreting a result. The two serial arms are not independent repetitions, and their steps must not be treated as independent trials.

This experiment makes no comparison with an NSCC timing and makes no official score or acceptance claim. A full matched pair on one allocation is evidence about this allocation and build; it does not establish repeatability by itself.
