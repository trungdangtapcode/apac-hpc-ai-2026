# Iris matched solver pair, 56 ranks

Offline payload draft for a same-allocation comparison of the retained hierarchical (7 4 2) cut and fresh Scotch cut. It requests one Iris node and 56 ranks, runs hierarchical then Scotch in that order, and gives each solver at most 3,900 seconds. A 300-second reserve is required before each solver starts; the internal job deadline is 8,700 seconds. The requested allocation is 2 hours 30 minutes. These gates bound work but do not guarantee that both arms will complete.

The comparison uses 150 time steps per arm with unchanged fixed linear-solver iteration counts, `simpleFoam -parallel`, the same OpenFOAM 2512 build, matched 56-rank placement, source fields, solver dictionaries and no-write policy. The only intended case definition differences are decomposition method with the same `nHierarchical (7 4 2)` expansion retained in both source dictionaries; both definitions specify `nCores 56`. Each arm receives an isolated full copy of the selected ready case. No initialized fields are changed and no initialization, cutting, or renumbering is run.

The run script expects the two source roots at the paths in `run-pair.sbatch`. It validates all 41 retained source pins, the exact source-specific `caseDefinition`, and READY contents before copying. Each arm copies only `system`, `constant`, and processor `0` plus `constant` into a new destination. Hashing, copying, dictionary edits, and a one-record-per-rank affinity preflight have explicit timeouts that share the internal deadline. The copy check hashes every regular file in scope, inventories symlink targets, and rejects shared inodes before any solver dictionary edits. The source manifest is checked again after each arm. It captures hardware, rank/affinity preflight, per-arm `/usr/bin/time -v`, complete solver logs, native timing and function-object timing series, Cd series, and fixed-iteration counters. `review-pair.py` uses only retained run manifests and output artifacts; it does not consult live remote source files. `offline_review.py` has H/S positive pin fixtures and negative numerical-drift, missing-field, unexpected-Allrun, copy-drift, and hardlink fixtures.

This is an offline draft, not a deployment or submission receipt. The matched comparison has not run and supports no solver-gain claim. One H-then-S pair leaves order effects unresolved.
