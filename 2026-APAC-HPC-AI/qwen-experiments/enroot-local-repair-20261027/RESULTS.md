# Direct Enroot accepted the variable; Pyxis did not apply it

Jobs 26531 and 26533 both failed before model startup in 17 and 18 seconds. Their allocated native preflight created the intended per-job /tmp directories and measured over 360/424 GB free, but actual Pyxis error paths still point at /data/enroot/data/user-3042 and fail ENOSPC. These are infrastructure failures, not measured control/candidate scores. No AIPerf ran. Frozen payloads remain unchanged.

The earlier CPU-only tiny squashfs test correctly proved that the installed Enroot CLI honors ENROOT_DATA_PATH. It did not test the Pyxis environment boundary. The official Pyxis source explicitly excludes ENROOT_DATA_PATH when importing the job environment into Enroot. This explains why exporting the variable alone was insufficient. Do not call the attempted deployment repaired or repeat it unchanged. Source: https://github.com/NVIDIA/pyxis/blob/main/pyxis_slurmstepd.c (enroot_deny_env / enroot_import_job_env, accessed 27October 2026). No plugin setting or administrator restriction was changed.

Actual allocated disk audit 26526 found g4 /data essentially full (about 2.65 GB available), while g1 /data had about 12.34 TB free. The shared BeeGFS /home and /scratch also expose the nearly full g4 volume. Our own default Enroot directory was empty on both nodes, so deleting stale own roots could not solve the full volume. No other user's data or retained research artifacts were deleted. Local NVMe root filesystems had approximately 360 GB and 435 GB available.

Next diagnostic 26538 uses direct unprivileged Enroot CLI inside an ordinary one-GPU Slurm allocation, with an explicit per-job user-owned /tmp path. It tests the real supplied image, CUDA visibility and a tiny tensor, not model inference. It preserves Slurm allocation/cgroup limits and changes no privileged plugin configuration. If this supported user-level path cannot run, do not queue full serving jobs on the predictably full default root volume; preserve evidence for site remediation. A direct-runtime serving wrapper is not accepted merely because a tiny CLI fixture passed.
