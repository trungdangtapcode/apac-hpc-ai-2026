## What was checked

The [publisher card/config](https://huggingface.co/nebius/EAGLE3-Qwen3-235B-A22B-Instruct-2507/tree/ff0f0c0999f6c86b21dfd2f5803eebc4ac712224) is pinned at ff0f0c0999f6c86b21dfd2f5803eebc4ac712224. Two bounded public HTTP Range requests read the eight-byte safetensors header length and 1496-byte JSON header: **1504 bytes total, no tensor payload**. Saved receipts contain stable repository/revision and range/status/size fields, not signed CDN URLs, cookies, tokens or authentication state. [Fetch receipt](header-fetch.json), [header](draft-safetensors-header.json).

The 15 named tensors match the inspected native Llama EAGLE3 structure: one layer, hidden size 4096, three concatenated 4096-wide target features feeding the FC projection, 64 query heads / four KV heads at head dimension 128, reduced 64000-token draft vocabulary and 151936-token target vocabulary. The declared floating tensors are BF16; the two vocabulary maps are I32. The native loader recognises the split projection names and vocabulary-map roles, with target embedding sharing handled by the EAGLE worker. Metadata shape consistency does not prove the tensor values, exact loaded-parameter coverage, valid token-map values, device execution or accuracy. Those remain runtime gates.

The pinned draft declares LlamaForCausalLM. The actual native ModelConfig._config_draft_model method, executed in isolation with this configuration, leaves that architecture unchanged. The inspected model loader resolves the declared architecture. [derived-draft-config.json](derived-draft-config.json) changes only architectures to LlamaForCausalLMEagle3, the class provided by the native draft module. It is a prospective **draft-only metadata adapter**, with no target-model/config/weight change and no tensor conversion. Do not apply a global model override that could accidentally replace Qwen's target architecture. A real load must still verify that the expected draft class and every required parameter actually load; the adapter is not deployed or certified.

Native Qwen3-MoE exposes auxiliary hidden-state capture for EAGLE3. The native speculative resolver uses three feature layers by default if draft layer IDs are absent. The draft FC input dimension matches three 4096-wide features. This does not validate the training/runtime layer convention or acceptance rate with the official FP8 target. An imperfect draft can simply be rejected more often; target verification must never be relaxed to compensate.

CPU fixtures execute the **actual native CommonKVManager.get_mha_kv_ptrs_with_pp** method for 94 target layers, without importing SGLang/Torch. Target-only, decode-only appended draft, and both-sides appended one-layer draft cases preserve respectively 188 / 188 / 190 ordered pointer pairs. The native prefill and decode setup append draft KV pointers after the main K/V pointers. Splitting the appended list into halves is not alone evidence of a transfer bug: in the matched case the concatenated pointer order is preserved. No speculative transport defect or fix is claimed by these fixtures. They do not check byte ranges, per-token/page strides, descriptor construction, actual NIXL registration or GPU transfers.

Native PD also passes draft top-k and hidden-state metadata. A decode-only KV helper pass does not establish EAGLE3 decode-only execution: the prefill side must supply compatible draft state and the metadata dimensions must agree. Start any future integration with draft support on both phases, inspect actual buffers and fallbacks, and validate the existing heterogeneous TP4→TP8 path. Keep the target, BF16 KV, P/D split and gateway unchanged. Do not assume all advertised speculative algorithms or all-to-all backends compose with HPC-Ops/MNNVL.

[check-interfaces.py](check-interfaces.py) retains executable CPU checks; [interface-checks.json](interface-checks.json) records the pass scope and source hashes. Native source snapshots and extraction receipts are retained. The first selective extraction failed because its parent directory did not exist; creating the parent and extracting into the new leaf succeeded. Two requested paths were absent; the corrected manifest lists actual extracted files. Later targeted extractions located the real worker/loader helpers. No full runtime module was imported or model inference/tensor computation executed on the login node; only two isolated pure methods run in the CPU fixtures.

## Next bounded test and stopping gates

Before a GPU pilot, stage the pinned public draft with an independently checked full-file digest outside Git, recording a recovery manifest. The header is insufficient to verify the weight file. Keep the untouched publisher config and derived config provenance. Explicitly use BF16/unquantized draft loading while preserving the published FP8 target; do not inherit target quantization accidentally. Confirm exact flag and metadata interfaces in this image.

Prepare a correctness-first H200 pilot when an existing queue position becomes available under the five-job cap. Retain all 16 GPUs, two TP4 prefill roles and TP8/EP8 decode, source kernels/transport and target context. Compare target-only and draft-enabled stages with all other settings held constant. Begin with a small fixed tree: two draft steps, top-k one and three draft slots only if the native convention confirms that combination. Capture loaded class/parameter coverage, target feature layers, both-phase draft KV/metadata geometry, verification attention/graphs, memory and runtime errors. Stop on infrastructure or numerical failure; no unchanged retries.

Every emitted token must be verified by the unchanged FP8 target under official greedy settings. Validate an actual token-ID/logprob observation route before claiming exact-token equality: matching decoded text alone is weaker evidence. Preserve the target-only reference requests and responses, generic/long-context diagnostics and each candidate mismatch. The organiser's 99%-of-reference full-set accuracy check remains unverified and is a separate gate.

Only after correctness works, run a short explicitly unranked load probe collecting accepted tokens per verification, draft/verify time, memory headroom, errors, TTFT and ITL at a fixed load. High concurrency can make speculative overhead dominate. Other-task acceptance lengths are not throughput predictions. A useful screen can justify a full matched official-protocol comparison and independent confirmation; otherwise close/refine the implementation. No candidate is promoted based on this CPU check, and there is no new score.
