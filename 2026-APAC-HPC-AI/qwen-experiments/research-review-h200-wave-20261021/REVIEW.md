## Collected evidence and limits

The raw AIPerf JSONL, phase manifests, role logs, router logs, client logs, long-context checks, output checks and diagnostic profile control records were inspected. Role log queue summaries in `REVIEW.json` cover all retained log events across startup, warmup, scoring and diagnostic activity; they are not phase-filtered. Their whole-log prefill queue maxima are 24 on both workers for 24964, 24965 and 25051, and 23 / 30 on prefill-0 / prefill-1 for 25283. Whole-log decode queue samples are zero. These maxima cannot be attributed to the scored interval or used to explain score differences.

The phase-aligned analysis in [phase-aligned-observability.md](phase-aligned-observability.md), generated by `review.py`, conservatively retains nominal five-second telemetry windows inside each `phase_manifest.json` profiling interval. It reports status counts inside scoring separately from startup/warmup/shutdown samples, compares observed GPU UUID sets with the 25051 locality receipt on the same named hosts, and gives per-device activity, sampled VRAM and power means and ranges. The scored interval contains 23–24 samples per role; all have GPU status `ok` and server HTTP 200 with metric payloads. The retained `URLError` server-scrape records are outside those intervals. The phase report includes role-level running-request, queue, token-usage, used-token and cache-hit gauges by labeled series, without summing across TP ranks; no inflight-request gauge was present. Any status or payload gap is left unknown, not zero. The sparse telemetry cannot establish between-sample peaks, a bottleneck, achieved FLOPS or score causality.

The diagnostic profile file inventory records four prefill trace filenames per worker and eight decode trace filenames per run outside scoring. The trace contents and kernel events were not inspected or aggregated. All three start-profile requests returned HTTP 200 with text bodies, but all three stop requests returned HTTP 500. The profile control lifecycle did not close cleanly; no kernel-time or scored-phase profile finding is claimed.

Job 25051's locality receipt maps all 4 prefill and 8 decode GPU UUIDs to the expected roles, with no ambiguous matches or truncated thread capture. It explicitly records that scored CPU demand was not collected. The evidence verifies process/GPU mapping only; it does not establish CPU saturation, memory placement, or performance causality.
