# H200 deterministic correctness diagnostic pair

## Question and evidence

The H200 EAGLE3 exact-token attempt 25797 completed startup, all-rank runtime and KV geometry checks, both semantic prefill/decode paths, and collected 1,600 actual output IDs. It failed the strict exact-output gate: code and Unicode repeats were stable but differed from the accepted target reference, while long4000 EAGLE3 passes differed from each other and the target reference. This remains a failure; this experiment does not change or repair its result.

The new hypothesis is limited: SGLang deterministic inference may make the target-only deployment repeatable after enabling batch-invariant operations. First run S44 through the same four-case/1,600-ID protocol and require exact target-a/target-b repeat stability, including requests, output IDs and finish reasons. The comparison against accepted job 25585 is retained as informational evidence only: deterministic mode changes kernels and collectives, so old target token identity is not an acceptance requirement. Only if S44 passes can S45 test EAGLE3 against that newly accepted deterministic target reference. This is a correctness diagnostic, not a performance experiment or expected speedup.

## Pinned source findings

Pinned source root: `dp-attention-ep-feasibility-20261024/pinned-source/sgl-workspace/sglang/python/sglang/srt`. `server_args.py` exposes `--enable-deterministic-inference` (line 3245 onward) and runs a native post-processing handler. `arg_groups/overrides.py` implements deterministic sampling as PyTorch, disables configured FlashInfer allreduce fusion, and selects FA3 by default on Hopper when global attention is unspecified; `server_args.py` sets NCCL tree allreduce and disables custom allreduce for CUDA TP greater than one. These are framework-native effects. The worker intentionally retains the `mnnvl` request so the framework handler can disable it; it does not manually force an alternative value.

The D role keeps explicit decode attention `flashinfer`, an allowed deterministic attention choice, while speculative draft attention remains FlashInfer as before. The deterministic handler does not itself rewrite the separate speculative-draft attention argument. Source review found no deterministic-specific branch in Qwen3-MoE or HPC-Ops MoE implementation. Therefore this mode does not establish that every EAGLE/HPC-Ops operation is deterministic; the candidate still requires strict actual-ID and repeat checks.

The source contract test reads the pinned source and verifies key option/handler text. It is a CPU/source assertion only. It cannot prove runtime resolution, GPU kernel behavior, output correctness, or determinism. The actual job gate requires fresh resolved `ServerArgs` records and actual per-rank BF16/NIXL records for all three roles. It also requires the framework's sampling, FlashInfer-disable, and TP-allreduce markers. Expected Hopper global attention is FA3; explicit D decode attention remains FlashInfer. Any mismatch fails closed.

## Matched protocol

S44 derives its target-only topology and request bodies from S38 and carries the S43 geometry observer for fresh native NIXL registration receipts. It adds deterministic inference, explicit disabled prefill CUDA graphs to match S43, and bounded geometry instrumentation. Target-only layout expects 188 KV regions from 94 model layers × two K/V regions. S43 EAGLE geometry has 190; the extra registration regions are not applied to target-only. The S44 D unknown-head exception is limited to role decode-0, TP8, PP0, page size one, 188 VRAM regions with 256-byte item/page/token strides; the head values remain not_collected. The runtime model and image preflight remains mandatory. The accepted baseline is job 25585, `runs/25585/target-reference.json`, SHA256 `a3b51d20cd6d67a3f659a5f84e6e787f319fb1e5464e5ddc912cdbdd78824c49`, with review seal `563938c2189174218de57ec2f771557766c766b4afafc2ac6af2b2cfc92f3980`. S44 acceptance requires the two new target passes to match each other for all four exact request bodies, 200 actual token IDs and finish reasons, totaling 1,600 actual IDs. The old 25585 comparison is emitted as informational evidence and cannot fail S44 acceptance.

S45 derives from S43 and retains its draft verification, rank/BF16 checks, S43 geometry and semantic P/D warmup, exact 1,600-ID collection, native speculative counters, and cold-cache request capture. It adds deterministic inference while retaining the requested MNNVL CLI flag for native disable and leaving draft FlashInfer unchanged. Candidate output must match both passes in the actual accepted S44 target receipt and match itself across EAGLE A/B. Its payload is blocked until root binds the real reviewed S44 job, result SHA, review JSON SHA and review seal into `target-reference-binding.json`; no job ID is guessed. Candidate runtime and result checkers read that binding and fail closed before it is populated.

Both bundles retain two H200 nodes, sixteen GPUs, 17-minute cap, native NIXL, explicit BF16 runtime gates, and no scoring workload. No job was submitted. S44 is prepared for review; S45 remains a non-frozen template pending S44 acceptance.

## Limits and next decision

SGLang's deterministic switch is a diagnostic intervention, not a universal guarantee for third-party kernels. A passing S44 would show target output repeatability for the frozen corpus and deployment. A passing S45 would show EAGLE3 exact equality for this corpus and deployment. Neither establishes official benchmark accuracy, production-wide deterministic behavior, or a performance change. Preserve 25585 as historical accepted baseline and 25797 as an unchanged failed attempt.
