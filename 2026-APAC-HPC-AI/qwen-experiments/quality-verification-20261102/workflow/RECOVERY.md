# Exact recovery dependencies

The immutable candidate checksum lists require two Python bytecode files in each of the eight bundles. These particular files are inputs to the entry checksum check, so they are retained explicitly in REQUIRED_BYTECODE.json and the archive. They contain compiled forms of the public local path helper and semantic warmup code, not credentials or model weights. Other generated bytecode/runtime caches remain excluded. This supplemental list preserves existing jobs without modifying their checksum lists or original 310-file manifest.

The finite completion workflow is an ordinary, bounded Slurm dependency flow for the fixed 16-shard measurement. It is not a recurring schedule, watcher or Codex process. It cannot select new hypotheses, retry jobs, change the scorer, request authentication or send messages. Code and required bytecode hashes must be guarded before wrapped job admission; actual Slurm terminal states are independently reconciled by the interactive worker. A callback records driver completion only.

The general capture policy prunes `__pycache__` directories even for explicit selections. Therefore the exact 16 reviewed files are retained in the small `required-bytecode.tar`, whose members are individually secret-scanned by the capture tool. This does not change cache policy or include other runtime caches. After restoring the Git source, run `python3 workflow/restore_required_bytecode.py` once from any directory; it verifies every member against the supplemental manifest and refuses different existing files. `--check-only` verifies an already present source tree without writing. The archive capture of the tar, rather than the pruned original paths, is the recovery evidence.
