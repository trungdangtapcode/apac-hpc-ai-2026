# Conditional direct-runtime control and larger-batch followup

Actual queued jobs are 26538 (one H200, four-minute rootless runtime probe), 26545 (16-H200 full N64 chunk 8192 control) and 26547 (same allocation, chunk 12288 candidate). Each serving job is limited to 17 minutes. The serving jobs wait in afterany order and must find an actual successful CUDA probe receipt before any model step; the prerequisite is not replaced by a CPU fixture. If the probe fails, no full model is started. This avoids an indefinitely unsatisfied dependency while keeping the scientific gate explicit.

Prior 26521/26524 failed before model startup on a nearly full g4 /data volume. Read-only 26526 proved the default own Enroot directory was empty and local NVMe had ample capacity. No other user's data or retained research was deleted. Attempted 26531/26533 then demonstrated that a variable honored by standalone Enroot is filtered by Pyxis. The original simple fix is not claimed successful. The official Pyxis source documents that environment exclusion; administrator configuration was never changed.

The new wrapper uses unprivileged native Enroot inside normal Slurm steps, retaining their CPU/GPU allocations and cgroups. Physical device IDs come from SLURM_STEP_GPUS; the cgroup-relative CUDA mask remains separate. All original source mounts, read-only transport patches, worker/model/client code and strict acceptance gates are retained. Parent worker and Python gate byte identity, shell/Python syntax, five launcher replacements, read-only mount argument generation and GPU mask separation have CPU preparation checks. Real GPU/image/mount/transport behavior remains unverified until the actual allocation runs. No score is inferred from those fixtures.

Both control and candidate use the same derived runtime. Compare them with each other before attributing a throughput change. The candidate tests the declared larger-batch/HPC-Ops interaction after smaller chunks lost, while retaining old 12288/auto-decode losses. It is not permission for a wide chunk sweep. Require full source/runtime/graph/KV/two-semantic-route/fixed-N64 raw workload and joint latency/output gates; then >1% useful valid paired gain before independent confirmation. Official full-set accuracy stays UNKNOWN.

The full image has an independently enumerated regular-file size upper bound of 30.635 GB (28.531 GiB). Per-step root filesystems are private, under local /tmp and removed only by their creating wrapper. A minimum 120 GiB free-space guard is imposed before extraction. Nothing is extracted into the already full shared /data or the research Git archive by this wrapper. Failure of the actual native runtime remains possible and must be reviewed as an infrastructure result.
