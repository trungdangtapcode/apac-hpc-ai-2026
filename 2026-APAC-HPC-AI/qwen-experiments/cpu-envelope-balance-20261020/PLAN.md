# Equal CPU budgets with balanced NUMA envelopes on H100

## Question and evidence

The actual full-model mapping in sealed 222435 is complete for all 16 GPU schedulers. All captured worker thread masks are already local. However, the ordinal PBS task envelope makes four NUMA 1 GPU schedulers share only eight CPU IDs. Prefill 0 has 32 local IDs; decode NUMA 0 has 56, while decode NUMA 1 has eight. Baseline goodput is 2413.341139 good output tokens/s, joint SLA 98.416887%, errors zero, long checks 12/12. There is no scored per-thread CPU-demand or host-memory-placement evidence, so this is not a proven CPU bottleneck.

Hypothesis: redistributing the same task CPU budget across GPU-local cores reduces host scheduling imbalance and improves goodput. Counter-hypothesis: GPU/memory/communication work dominates, so the envelope change is neutral or worse. Keep the existing SGLang NUMA behaviour; the actual observation does not justify disabling it or treating the static one-GPU remote mask as the full-serving state.

Balanced partitions one allowed hardware thread per physical core among the node's eight GPUs in deterministic NVML order within each NUMA group, then selects partitions by actual CUDA UUID. This ordering is not an assumption that CUDA/NVML ordinals match. Each GPU receives eight CPU IDs in the outer envelope. UUID-based partitioning also handles interleaved CUDA ordering without overlapping prefill envelopes.
