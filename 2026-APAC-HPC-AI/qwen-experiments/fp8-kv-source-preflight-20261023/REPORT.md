# FP8 KV source preflight

**Decision:** Source-qualified for a bounded one-GPU primitive; **hold full-model or P/D FP8-KV work** until scale provenance is established and the primitive confirms the installed FlashInfer path. This is a source review, not a runtime result or an accuracy claim.

The pinned contest rules allow the published Qwen3-235B FP8 weights with FP8 KV storage. The exact SGLang option is `--kv-cache-dtype fp8_e4m3`; keep the weight checkpoint and all other serving settings fixed. The rules' full-set accuracy threshold is 99% of the official reference, and no local evidence reviewed here establishes that gate.

## Minimal next diagnostic

Run a single-GPU, tiny synthetic primitive on one H200 using the pinned image and native FlashInfer. Do not load Qwen weights. Construct the smallest supported NHD KV pool with the intended local head geometry; set only `--kv-cache-dtype fp8_e4m3` (and retain the same attention backend). Record the resolved logical dtype, `store_dtype`, actual K/V tensor shapes and strides, per-buffer `get_contiguous_buf_infos()` `item_lens` and `lens`, page size, FlashInfer wrapper dtype, scale values/source, and a minimal FP8 cache write plus attention read. Compare descriptor output with BF16 from the same geometry. This tests storage and kernel plumbing without guessing numeric widths in advance.

The primitive would **not** prove Qwen accuracy, EAGLE3 token equivalence, calibrated scales, full-model memory fit or performance, P/D transfer correctness, heterogeneous-TP NIXL interoperability, or MNNVL fabric operation. If it passes and scale provenance is resolved, a separate matched precision/quality gate is still required before full-model use; do not claim the official 99% threshold without the full-set check.
