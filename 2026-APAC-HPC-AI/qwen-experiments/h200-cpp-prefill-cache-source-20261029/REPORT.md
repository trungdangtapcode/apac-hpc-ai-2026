# Experimental C++ radix cache: source feasibility review

**Review date:** 2026-10-29 (UTC). **Status:** source reviewed; no job submitted and no GPU/runtime measurement made.

## Finding

The pinned SGLang image contains an opt-in C++ radix-tree implementation that is a plausible, separate prefill-cache candidate. `registry.py` checks the chunked-prefill plus `disable_radix_cache` branch first. Only if that branch does not return does `SGLANG_EXPERIMENTAL_CPP_RADIX_TREE` lazily select `RadixCacheCpp`. Therefore a C++ candidate must keep prefill radix enabled (`disable_radix_cache=False`); the existing prefill ChunkCache candidate is a different treatment. Decode can remain unchanged on ChunkCache.

The native extension is **not prebuilt** in the inspected image. `cpp_radix_tree/radix_tree.py` imports `torch.utils.cpp_extension.load` and JIT-compiles `tree_v2_binding.cpp`, `tree_v2_debug.cpp`, and `tree_v2.cpp` using `-O3 -std=c++20` on first import. The first source snapshot omitted `tree_v2_debug.cpp`; this was corrected on 2026-10-29 by adding the exact image file, byte count and SHA-256 to the evidence and manifest. The initial snapshot is historical and incomplete; the corrected manifest covers all three translation units. This is host C++ compilation; the extension source list contains no CUDA source. A first-use CPU-only build/fixture is feasible on an allocated compute node with the exact container, installed PyTorch headers/libraries, a working C++20 compiler and Ninja/build prerequisites. It must not be attempted on the login node. A concurrent multi-rank startup can trigger first-use builds on each host; retain per-rank startup timing and check that all eight selected prefill ranks report the C++ backend.

## Compatibility and limits

- The class implements `BasePrefixCache` and the ordinary prefix match, insertion, request-finish, unfinished-request, eviction and lock-ref methods used by the cache lifecycle. Its `cache_finished_req` and `cache_unfinished_req` preserve request KV ownership/reuse and release cache locks, matching the expected P-side interface. This source inspection is not proof that the full disaggregated runtime's successful-transfer release path is correct with this alternate class; verify it in a full startup/semantic qualification before scoring.
- The C++ tree stores token keys and KV-index tensors. It does not alter model weights, FP8 weight kernels, attention, CUDA graphs or disaggregation transport directly. That makes FP8 and graph settings orthogonal in principle, not experimentally verified.
- The candidate is for the two prefill TP4 workers only, preserving P4 + P4 / D8 TP8 EP8 and the decode ChunkCache/flags. Current recorded model startup reports `hybrid_swa=False` and `hybrid_ssm=False`, avoiding the hybrid-cache branches. The C++ implementation rejects KV-cache events and hierarchical/host cache; keep those disabled as in the pinned baseline.
- Native `RadixTreeCpp` is CPU-fixture testable with CPU `torch.int64` index tensors. A low-level fixture can test insert, exact/prefix match, duplicate reuse, split-prefix and eviction/lock invariants without loading Qwen or allocating a GPU. That only tests the data structure and JIT toolchain. It does **not** validate the full `RadixCacheCpp` allocator, distributed P/D transfer, rank agreement, output quality or performance.

## Recommended bounded preflight

Before spending a 16-GPU scored allocation, run one single-process, zero-GPU allocation in the same image, capped at 2 CPU cores and 2 minutes. Import the exact `radix_tree.py` module (thereby exercising first-use JIT build), create `RadixTreeCpp(disabled=False, host_size=None, page_size=16, write_through_threshold=1)`, insert deterministic 32-token keys with CPU `int64` index tensors, and assert: initial insert reports 0 matched tokens; exact repeat reports 32 and returns the original indices; a 16-token prefix returns the first 16 indices; an overlapping key exercises a split without changing earlier mappings; an unlocked eviction frees only evictable entries; a locked prefix cannot be evicted. Save compiler/import output and assert no CUDA device is visible/used. If compilation exceeds 2 minutes or toolchain prerequisites are absent, mark the preflight failed and do not silently widen it.

If the CPU fixture passes, stage (but do not score yet) a single matched full-model candidate against the fresh native RadixCache control: enable only `SGLANG_EXPERIMENTAL_CPP_RADIX_TREE=1` for both P workers, keep P `disable_radix_cache=False`, leave D and every other flag unchanged, and require all four ranks on each P worker to log the experimental C++ selection and resolve to `RadixCacheCpp`. Then verify allocation/rank ownership, transfer completion/release, output smoke and original raw gates before AIPerf. Do not combine this with the separate prefill ChunkCache switch or compile/cap changes.
