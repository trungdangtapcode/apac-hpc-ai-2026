## Exact packaged-entry acceptance — 2 November

Job **28194** exposed the final deployment issue: the gateway health endpoint returned HTTP 200 while asynchronous worker registration was incomplete, and the immediately checked `/v1/models` endpoint returned HTTP 503. The process had no scored AIPerf result. The bounded fix changed only readiness: verify a valid registered Qwen model and live `srun` workers under the original job-start-plus-600-second deadline. It preserved the model, serving parameters, semantic checks, official benchmark command and result-reading criteria. Five local readiness/liveness fixtures passed before the final run.

The corrected exact packaged entry, job **28197**, completed in **611 seconds** on 16 H200 at N64, passed both P/D semantic routes, corrected readers, the performance gate and cleanup, and scored **3,051.518173 good output tokens/s**. Of 1,907 performance requests, **1,881 (98.636602%)** met both latency limits; 26 missed TTFT, zero missed ITL, and there were no request errors/cancellations. There is no matched control in this entry test, so this is not a measured optimisation gain or new serving recipe.
