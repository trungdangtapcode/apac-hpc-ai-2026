# 27 October: move the qualified pin mechanism into the real Pstream boundary

**Question and prior evidence.** Native job 26016270 keeps every one of 512 main threads pinned across collectives and a two-second wait, and its targets reproduce entry placement. That does not show that a separate library can apply the same mechanism at actual OpenFOAM initialization and survive application shutdown.

**Controlled change.** The new bundle has three bounded arms: unchanged native control, that control through a PMPI adapter, and real parallel checkMesh through the adapter on an owned 8,192-cell diagnostic mesh. All use 512 ranks across four CPU nodes. No contest solver or official mesh is modified. The adapter forwards to the underlying MPI implementation, waits until initialization succeeds, validates topology and all-rank preflight, then pins the calling thread only. It records actual init levels and process/thread identities, pre-finalize masks and the actual PMPI_Finalize return using OS-only I/O afterward. The worker injects preload only into the target rank executable.

**Actual interface and validation.** Installed Pstream source SHA-256 and dynamic symbols identify MPI_Init_thread and MPI_Finalize; the null-argument path is supported. Compiler-wrapper output confirms its specific GNU MPI library, and the job will link and recheck the exact runtime used by Pstream. Offline C grammar, shell and Python checks pass; a declaration-only header is not MPI ABI evidence. Synthetic rejection fixtures and 1,024 real native records exposed and corrected a world_size schema assumption before deployment. A local declaration-header failure was also corrected; its draft seal/header are retained. The root review adds frozen-manifest equality, full utility version/precision/rank/cell-count proof, and post-finalization return audits.
